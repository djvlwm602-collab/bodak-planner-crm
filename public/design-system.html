§ 11 Naming ConventionsPhase 8-A 도입

토큰 이름은 prefix-suffix 룰 로 카테고리·상태·위계를 표현. 신규 토큰은 본 룰을 따른다 — § 6.4 도메인 토큰의 임의 명명은 Phase 8-D 에서 alias 비파괴 마이그레이션 완료.

Prefix 규칙 (카테고리)

Prefix용도
bg-*모든 배경 (색·tint·hover)
text-*텍스트 색
border-*테두리
button-*버튼 컴포넌트 전용
status-*상태/의미 (info / pending / done / success / error / warning)
chart-*차트 (axis / grid / tooltip / series)
modal-*모달 영역
icon-*아이콘
bg-emphasis-*강조 배경

Suffix 규칙

Suffix의미
-hover / -active / -disabled / -pressed상태
-bg / -fgbg/fg 분리 시
-primary / -secondary / -tertiary위계
-subtle / -faint / -strong농도

금지 패턴

// 카테고리 prefix 누락 ❌ --row-stripe → ✅ --bg-row-stripe // prefix 와 suffix 가 같은 카테고리 중복 표지 ❌ --kanban-column-bg → ✅ --bg-kanban-column // 상태인지 컴포넌트인지 모호 ❌ --danger-hover → ✅ --button-danger-hover
기존 도메인 토큰은 Phase 8-D 에서 신규 이름으로 마이그레이션됨. 구 이름은 deprecated alias 로 1년 (2027-04-29) 까지 유지.

§ 12 신규 색 추가 결정 트리Phase 8-A 도입

새 색이 필요할 때 *어떤 Tier* 에 추가할지 판단. Tier 2 우선, 도메인은 차순위. 도메인 토큰은 Tier 2 의 특수 변종 역할 — 별도 카테고리가 아님.

Q1. brand 별로 달라져야 하는 색? YES → Brand 인터페이스 확장 (palette.tertiary 등) NO → Q2 Q2. 동일 의미로 N 곳 반복 사용? 1~2 회 단발: Value 직접 참조 (chart-series-3 = violet-400 패턴) + 재발 시 Q2 재평가 주석 3+ 회 반복: Q3 Q3. 상태/의미 표현 vs 시각 변형? 상태/의미 (badge, alert): 도메인 토큰 신설 (--status-* 패턴) 시각 변형 (hover, stripe): Q4 Q4. 기존 Tier 2 로 표현 가능? YES: Tier 2 사용 (예: bg-bg-tertiary 가 light bg 충분) NO: Tier 2 확장 (예: --bg-quaternary 신설)
신규 색 발생 시 Tier 2 확장이 가능한지 먼저 검토. 도메인 토큰은 정말 의미가 *Tier 2 로 표현 안 될 때* 만 신설.

운영 가이드 (Contributing)Phase 8-E/F

신규 토큰·컴포넌트·브랜드 추가 절차 + lint:tokens 거버넌스 + PR 템플릿. 자세한 절차는 docs/CONTRIBUTING.md.

신규 토큰 추가 절차 (8단계)

  1. § 12 결정 트리 통과 — Tier 2 우선 검토, 도메인은 차순위.
  2. § 11 네이밍 컨벤션 준수 — bg-* / text-* / border-* / button-* / status-* / chart-* 등 prefix.
  3. @brand-free / @brand-safe / @reserved 주석 명시 — applyBrand 갱신 대상 vs 시스템 잠금 vs 의도된 reserve.
  4. src/styles/tokens.css + src/index.css @theme 양쪽 갱신.
  5. design-system.html 시각화 추가.
  6. npm run lint:tokens 통과 (전체 audit).
  7. npm run lint:tokens:check 통과 (Phase 8-F PR 시점 강제 — 신규 토큰 사용처 / @reserved / @deprecated 분류).
  8. PR 템플릿 체크리스트 모두 통과.

lint:tokens 거버넌스

# 전체 audit (그룹별 / 카테고리별 미사용 + Reserved 목록) $ npm run lint:tokens # JSON 출력 (CI / 자동화) $ npm run lint:tokens:json # PR 시점 강제 (default --since=main) $ npm run lint:tokens:check # 비교 기준 override (HEAD~1 / origin/main 등) $ npm run lint:tokens:check:since=HEAD~1
위반 시 exit 1 + 가이드 메시지: (1) 즉시 사용처와 함께 추가, (2) /* @reserved */ 주석 추가, (3) 토큰 정의 자체를 PR 에서 제거.
